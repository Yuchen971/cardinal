# 变更记录

这份记录写 fork 版 Cardinal 相对官方版本改了什么。官方自己的发布记录在根目录的 CHANGELOG.md，两边分开写，同步官方更新时不会冲突。

## 2026-10-22

### 其他应用可以用 Cardinal 搜文件

为接下来的 Tuna 插件做准备：Tuna 这类启动器可以把关键词交给 Cardinal，拿回结果列表显示在自己的界面里。

- **什么时候能用**：只要 Cardinal 在运行就能用，关掉窗口、只在后台运行时也可以。没有开关，打开 Cardinal 就生效。
- **安全**
  - 只接收这台电脑上的请求，局域网和外网都连不进来。
  - Cardinal 每次启动时生成一把新的访问钥匙，存在只有当前用户能读的文件里。没带钥匙的请求一律拒绝，所以网页无法偷偷查你电脑上有哪些文件。
  - Cardinal 退出时删除这个文件。
- **怎么搜**：搜索语法和 Cardinal 窗口完全一样，`ext:pdf`、`size:>100MB`、`in:~/Documents` 等都能用。默认不区分大小写，可以选择区分。
- **返回什么**
  - 每条结果：名称、完整路径、类型（文件、文件夹或替身）、大小（只有文件有）、修改时间、创建时间。
  - 另外返回一共匹配了多少条。
  - 默认返回 50 条，最多 200 条。
- **排序**：只影响给其他应用的结果，Cardinal 窗口里的排序不变。
  1. 系统文件、应用内部文件、缓存、代码依赖、编译生成的文件（`target`、`build`、`dist` 文件夹里的）和隐藏文件，一律排在最后，不管名字多匹配。只是往后放，不会被隐藏。
  2. 其余结果先看文件名：和关键词完全一样的排最前，然后是以关键词开头的，最后是名字里包含关键词的。判断"完全一样"时不看扩展名，搜 `report` 时 report.pdf 也算。
  3. 再看位置：个人文件夹里的排在其他位置（例如"应用程序"文件夹、外接硬盘）前面。
  4. 同一档里，最近修改过的排前面。
  - 为什么系统文件要一律排最后：最初的规则是"先名字、后位置"。实测时发现，只输入一两个字母时，前几条全是名字刚好一样的系统文件。例如搜 `a`，排第一的是 `/System/Library/Frameworks/AGL.framework/Versions/A`。
- **速度**（在 463 万个文件上实测，Cardinal 在后台运行）：输入一个字母约 0.33 秒，两个字母约 0.1 秒，三个字母及以上不到 0.06 秒。
  - 窗口不在前台的应用会被 macOS 降低运行速度（"应用休眠"）。启动器调用 Cardinal 时，它一定在后台，之前只输入一个字母的搜索要 1.4 秒。现在 Cardinal 处理其他应用的搜索时，会暂时告诉系统不要降速，处理完就恢复，不影响平时的耗电。
- **状态**：Cardinal 第一次扫描全盘、还没扫完时，会返回"正在建立索引"和已扫描的文件数，而不是一个空列表。
- **连续输入**：用户在启动器里快速打字时，新的搜索会取消上一次还没完成的搜索。不会打断 Cardinal 窗口里正在进行的搜索。

### 在 Cardinal 里看全部结果

- 其他应用可以让 Cardinal 弹出窗口，并在搜索框里填好同样的关键词，直接显示全部结果。Tuna 列表最后一条 "Show all results in Cardinal" 用的就是这个功能。
- 如果窗口当时停在 "Events" 标签，会自动切回 "Files" 标签。
- 这次改动没有增加新的界面元素。
